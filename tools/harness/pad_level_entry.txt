# Pad-side level-entry timeline -- dense START pulses, for uinput_inject.py.
#
# The headless bot's ai_menu_start.txt CANNOT be used on hardware: its rows are
# engine flag words (400 = FLAG_START) written straight into
# playercontrolpointers[0] inside inputrefresh(). This file is the device-side
# equivalent -- evdev button names injected upstream of MiSTer Main.
#
# STRATEGY (borrowed from the headless bot): most OpenBOR PAKs advance every
# intro / title / menu / character-select screen on START, so mashing START
# walks the whole chain into gameplay without knowing the PAK's menu depth.
#
# 🛑 SIZE THIS FOR THE DEEPEST MENU CHAIN YOU EXPECT, NOT FOR ONE PAK.
# Menu depth varies per PAK and there is NO way to detect arrival from outside
# the process, so an under-provisioned timeline silently stops partway and looks
# exactly like a broken mechanism. Measured on ATOV: 24 pulses reached the intro
# splash, 64 reached CHARACTER SELECT, and both were misread as "START does not
# work" before someone looked at the screen. The headless bot uses 150 for this
# reason. 150 is the floor, not a tuned value.
#
# 🛑 THE ONE DIFFERENCE FROM THE HEADLESS BOT: it auto-stops the instant
# `level != NULL`. We cannot see that variable, so these pulses keep firing
# after the level loads -- and in-level START opens the PAUSE MENU.
#
# Survivable BY CONSTRUCTION, not by luck: with the pause menu open,
# `pauselector` starts at 0 = Continue and START confirms, so pulse N opens the
# menu and pulse N+1 selects Continue and closes it. An EVEN number of surplus
# pulses nets to closed. KEEP THE COUNT EVEN. 150 is even.
#
# 🛑 VERIFY THE OUTCOME, DO NOT INFER IT. fps is ~85 on a menu AND in a level,
# so it proves nothing about which screen you are on. Confirm a player entity
# exists (the pause menu only opens with one) before starting a recording step.
#
