## A. The design change

🛑 **A THIRD FRAMEBUFFER IS NOW MANDATORY.** The reader latches `buf_base_addr` **once per
vsync** (`openbor_video_reader.sv:517-536`, reached only from `ST_IDLE`) and then streams that
buffer for the whole ~16.7 ms frame. So publishing `b^1` mid-frame does **not** retire `b` —
and the round-4 target rule handed `b` straight to the compositor, which starts in
microseconds. Tearing up to a full frame wide.

With two framebuffers the correct rule serialises the compositor behind scanout and destroys
the throughput case. BUF2 is therefore a **memory-map change before Phase 2**, not a Phase-2
option — and it also gives `[DCV16]` a private scratch target, which dissolves that item too.

| C6 | Strict priority is unimplementable: every reader issue point is gated on `!ddr_busy`, so a masked reader **never raises `ddr_rd`** and the arbiter sees no request — starving it every line | reader needs a **`wants_bus`** output ungated by `ddr_busy`; added to the phase-1c prerequisite list |

**Architecture MAJORs:** `fifo_aclr` cannot cancel outstanding Avalon returns, so the named
swallow recovery does not recover; He-Man was never checked against the ~1 px/clk fetch bound
(≈10.9 ms of a 16.7 ms frame on the fetch engine alone); §14.2 and §15 stated the compositing
rate with the binding constraint removed; the doorbell still has no retire semantics; the
`[DCV16]` frame-mode proposal deadlocks after one probe frame.
